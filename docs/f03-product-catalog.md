# ChairX F03 — Каталог товаров и вариаций

## Цель и границы пакета

F03 добавляет **реальную** работу с моделями кресел и их вариациями в уже
существующий F02.1 frontend. Все данные приходят из backend PostgreSQL REST
API. Не используется ни одной фиктивной записи, автоматически сгенерированного
SKU или нового backend endpoint.

F03 не включает складские остатки, закупки, продажи, фотографии, импорт Excel,
финансы, себестоимость и автоматические исторические перерасчёты.

## Страницы

- **/catalog** — серверная пагинация моделей (20 записей), название,
  категория, статус активности, переход в карточку. Кнопка создания
  доступна только с \`CATALOG_MANAGE\`.
- **/catalog/:productId** — реальные данные модели: название, категория,
  описание, статус, дата создания/обновления; отдельный список вариаций с
  пагинацией. Для управления моделью и вариациями требуется \`CATALOG_MANAGE\`;
  только для чтения — \`CATALOG_READ\`.
- Адаптивная верстка: таблица на широком экране, карточки на мобильном.
  Существующие Sidebar, Header и Breadcrumbs не заменяются.

Модель и вариация — **разные UUID**. Создание вариации не создаёт вторую
модель. Цена относится к вариации, а не к складу.

## API и реальные поля DTO

| Операция | Endpoint | Permission |
|---|---|---|
| Список моделей | GET /api/products?page=N&size=20 | CATALOG_READ |
| Карточка модели | GET /api/products/{id} | CATALOG_READ |
| Создать модель | POST /api/products | CATALOG_MANAGE |
| Изменить модель | PUT /api/products/{id} | CATALOG_MANAGE |
| Вкл./выкл. модель | POST /api/products/{id}/activate или /deactivate | CATALOG_MANAGE |
| Список вариаций | GET /api/products/{id}/variants?page=N&size=20 | CATALOG_READ |
| Создать вариацию | POST /api/products/{id}/variants | CATALOG_MANAGE |
| Изменить вариацию | PUT /api/product-variants/{id} | CATALOG_MANAGE |
| Вкл./выкл. вариацию | POST /api/product-variants/{id}/activate или /deactivate | CATALOG_MANAGE |

GET отдельной вариации (\`/api/product-variants/{id}\`) также поддерживается
существующим API-клиентом каталога; F03 редактирует только значения,
фактически полученные из server-paginated списка вариаций.

Ответ \`ProductPageResponse\`/\`ProductVariantPageResponse\`:
\`items\`, \`page\`, \`size\`, \`totalElements\`, \`totalPages\`. Никаких
\`variantCount\` у Product нет: каталог не запускает N+1 запросы.

Request модели: \`name\` обязательно <=200, \`category\` <=120 или null,
\`description\` <=4000 или null.

Request вариации: \`name\` обязательно <=200, \`color\` <=100 или null,
\`sku\` <=100 или null, \`recommendedSalePrice\` обязательно,
неотрицательное и не более 17 целых / 2 дробных знаков. В форме ввод
\`8500,25\` нормализуется к десятичной JSON-строке \`"8500.25"\`,
которая принимается Jackson BigDecimal. Числовых бизнес-вычислений через
JS float нет; форматирование для отображения не меняет сохранённую цену.

Цвет — свободное текстовое поле с подсказками распространённых цветов.
Автоматической генерации SKU нет.

## Permissions и ошибки

F03 использует **существующий F02 AuthProvider** и эффективные permissions,
а не жёсткую проверку ADMIN/MANAGER. В случае отсутствия \`CATALOG_READ\`
доступ к /catalog и /catalog/:productId закрыт; \`CATALOG_MANAGE\` открывает
только действия редактирования при наличии необходимого права чтения.
Серверный SecurityConfig остаётся окончательным источником прав.

Запросы идут через общий \`apiClient\`, включая Basic Authorization,
CSRF для POST/PUT, cookie same-origin и существующую обработку 401. На 403,
400/422, 409, 404, 5xx, сбой сети и некорректный JSON отображаются
безопасные сообщения (без внутренних stack traces). Ошибка mutation не
закрывает форму; введённые поля сохраняются. На время сохранения форма
блокирует повторную отправку. Деактивация сопровождается подтверждением,
она не удаляет запись и не затрагивает исторические продажи.

В Query cache используются ключи \`['catalog','products',page]\`,
\`['catalog','product',id]\`, \`['catalog','variants',id,page]\`.
После создания/изменения отправляется адресная invalidation, карточка
обновляется через setQueryData. AuthProvider F02 очищает QueryClient
при смене пользователя и выходе.

## Известные ограничения backend

**Серверные search/status/category отсутствуют** для GET /api/products.
Поэтому F03 не делает вид, что поиск только по текущей странице означает
глобальный поиск. В интерфейсе это объяснено пользователю; действующая
серверная пагинация остаётся корректной. Если потребуется поиск —
добавить опциональные серверные параметры отдельным backend-пакетом.

ProductPageResponse не содержит количества вариаций, поэтому F03 не
показывает фиктивный счётчик вариаций на главном списке.

Spring Boot сериализует BigDecimal как JSON number. JavaScript при разборе
очень больших чисел (выше Number.MAX_SAFE_INTEGER) может терять точность:
такие финансово значимые операции должны быть решены отдельным API
контрактом decimal-as-string до поддержки экстремальных сумм. F03 не
выполняет с ценой арифметики и отправляет точную строку.

При обновлении страницы F02 допускает повторный вход, поскольку
credentials хранятся только в памяти. Это ожидаемое поведение безопасности.

## Состав компонентов

- \`features/catalog/types.ts\`: типы DTO.
- \`features/catalog/api.ts\`: CRUD и query keys.
- \`features/catalog/validation.ts\`: валидации, подсказки цветов и форматирование KGS.
- \`features/catalog/pages/CatalogPage.tsx\`: модельный список и создание.
- \`features/catalog/pages/ProductDetailPage.tsx\`: карточка, варианты, изменение и переключение активности.
- \`features/catalog/components/ProductForm.tsx\`, \`VariantForm.tsx\`: переиспользуемые формы с сохранением значений при ошибке.
- \`features/catalog/components/CatalogPager.tsx\`: серверная пагинация.
- F02.1 маршрутизатор подключает новый динамический путь и карточку без
  изменения остальных разделов, Sidebar и навигационных групп.

## Проверки и дальнейшая интеграция

\`\`\`sh
cd frontend
npm ci
npm run lint
npm run typecheck
npm run test
npm run build
\`\`\`

Frontend Vitest проверяет реальный рендеринг списков и форм на тестовых HTTP
ответах, маршруты, CRUD-запросы и заголовки Basic/CSRF, pagination, custom
roles/read-only, сбои сервера, повторы и decimal format. Рабочий интерфейс
не содержит заглушечных записей.

В следующих пакетах склад/закупки/продажи будут ссылаться на реальные
\`productVariantId\`, но не станут зависеть от F03-состояния формы.
